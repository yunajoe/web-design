# **웹디자인 컬러 사용법: UI 컬러 시스템과 디자인 토큰 이해하기**

## **1. UI 컬러의 역할**

UI에서 컬러의 목적은 화면을 예쁘게 꾸미는 것이 아니라 **정보와 행동의 우선순위를 구분하는 것**이야.

컬러를 통해 사용자는 다음을 빠르게 파악할 수 있어.

- 어떤 행동이 중요한가?
- 무엇을 클릭할 수 있는가?
- 현재 어떤 항목이 선택되었는가?
- 성공·오류·주의 상태는 무엇인가?
- 핵심 정보와 보조 정보는 무엇인가?

## **2. UI에서 사용하는 네 가지 컬러**

| 종류        | 목적               | 사용 예시                  |
| ----------- | ------------------ | -------------------------- |
| 브랜드 컬러 | 브랜드 정체성 표현 | 로고, 브랜드 그래픽        |
| 액션 컬러   | 사용자 행동 유도   | 버튼, 링크, 선택 메뉴      |
| 중립 컬러   | 화면 구조 구성     | 배경, 텍스트, 카드, 테두리 |
| 시맨틱 컬러 | 시스템 상태 전달   | 성공, 오류, 주의, 정보     |

### **① 브랜드 컬러(Brand Color)**

브랜드의 정체성과 인상을 나타내는 대표 색상.

- 로고와 브랜드 그래픽에 반복적으로 사용
- 화면 전체에 남용하지 않기
- 중요한 영역에 제한적으로 사용하면 브랜드 컬러가 더 돋보임

### **② 액션 컬러(Action Color)**

사용자가 클릭하거나 선택해야 하는 요소에 사용하는 색상.

- 버튼
- 링크
- 현재 선택된 메뉴

브랜드 컬러를 액션 컬러로 함께 사용할 수 있지만 반드시 같을 필요는 없어.

핵심은 사용자가 클릭 가능한 요소를 쉽게 알아차리는 것.

### **③ 중립 컬러(Neutral Color)**

실제 UI에서 가장 많이 사용하는 색상으로, 주로 그레이 계열을 사용해.

**사용 영역**

- 배경
- 텍스트
- 카드
- 입력창
- 테두리
- 구분선

보통 하나의 회색만 사용하는 것이 아니라 여러 단계로 구성해.

`Gray 50 → 100 → 200 → ... → 900`

서비스 분위기에 따라 다음처럼 구분할 수도 있어.

- Cool Gray: 푸른 느낌이 섞인 회색
- Warm Gray: 따뜻한 느낌의 회색

### **④ 시맨틱 컬러(Semantic Color)**

시스템의 상태와 의미를 전달하는 색상.

| 상태 | 일반적인 색상 | 사용 예시   |
| ---- | ------------- | ----------- |
| 성공 | Green         | 저장 완료   |
| 오류 | Red           | 입력 오류   |
| 주의 | Yellow        | 확인 필요   |
| 정보 | Blue          | 안내 메시지 |

**주의:** 색상만으로 상태를 전달하면 안 돼. 오류라면 빨간색뿐 아니라 오류 아이콘과 설명 문구도 함께 제공해야 해.

## **3. 강조 컬러는 적게 사용하기**

포인트 컬러를 화면 곳곳에 사용하면 오히려 강조 효과가 사라져.

예를 들어 쇼핑몰에서는 다음과 같은 요소에 강조 컬러를 집중할 수 있어.

- 할인율
- 타임세일
- 구매 버튼

**모든 요소가 강조되면 결국 아무것도 강조되지 않아.**

## **4. 텍스트 컬러에도 위계가 필요하다**

텍스트의 중요도에 따라 색상의 강도를 다르게 설정해.

| 텍스트 종류 | 컬러 강도    |
| ----------- | ------------ |
| 제목        | 강한 색      |
| 본문        | 기본 색      |
| 설명        | 조금 연한 색 |
| 부가 정보   | 더 약한 색   |

단, 부가 정보라고 해서 지나치게 연하게 만들면 가독성이 떨어질 수 있어.

## **5. 컬러와 웹 접근성**

컬러를 결정할 때는 텍스트와 배경 사이의 **명도 대비**를 확인해야 해.

- 대비가 부족하면 텍스트를 읽기 어려움
- 시력이 좋지 않은 사용자에게 불편함을 줄 수 있음
- 밝은 환경에서 화면을 보는 경우에도 가독성이 떨어질 수 있음

따라서 예쁜 색상보다 실제로 읽을 수 있는 색상을 우선해야 해.

## **6. 하나의 색상도 여러 단계로 만들기**

메인 컬러가 파란색이라면 파란색 하나만 사용하는 것이 아니라 여러 단계의 팔레트를 구성해.

**Blue Color Scale**

50

100

200

300

400

500

600

700

800

900

색상 단계 예시. 실제 서비스의 팔레트 값은 디자인 시스템에 따라 달라질 수 있어.

버튼을 예로 들면 상태마다 다른 색상 단계를 연결할 수 있어.

| 상태     | 의미                        |
| -------- | --------------------------- |
| Default  | 기본 상태                   |
| Hover    | 마우스를 올린 상태          |
| Pressed  | 누르고 있는 상태            |
| Focus    | 키보드 등으로 포커스된 상태 |
| Disabled | 비활성화 상태               |

이런 규칙을 만들면 새로운 화면을 추가해도 일관된 UI를 유지할 수 있어.

## **7. 컬러 토큰으로 역할 관리하기**

디자인 시스템에서는 실제 컬러 값과 사용 목적을 분리해서 관리할 수 있어.

강의에서는 이를 두 가지로 구분해.

### **① Primitive Token**

실제 색상 값을 의미해.

예시:

- `Blue 500`
- `Gray 900`
- `Red 500`

### **② Alias Token**

실제 색상이 어디에 사용되는지 역할을 나타내.

예시:

- `Text Primary`
- `Background Primary`
- `Border Default`
- `Action Primary`
- `Error`

| 구분 | Primitive Token | Alias Token      |
| ---- | --------------- | ---------------- |
| 의미 | 실제 색상 값    | 색상의 사용 목적 |
| 예시 | Blue 500        | Action Primary   |
| 특징 | 색상 중심       | 역할 중심        |

**컬러 토큰 연결 예시**

**Alias Token**

Action Primary

**Primitive Token**

Blue 500 · #3B82F6

**실제 버튼 배경색**

이렇게 관리하면 실제 컬러가 변경되어도 역할 자체는 유지할 수 있어.

## **8. 다크 모드에도 같은 역할을 사용할 수 있다**

Alias Token을 사용하면 라이트 모드와 다크 모드의 컬러를 쉽게 관리할 수 있어.

| Alias Token        | 라이트 모드 | 다크 모드 |
| ------------------ | ----------- | --------- |
| Background Primary | White       | Gray 900  |
| Text Primary       | Gray 900    | White     |
| Border Default     | Gray 200    | Gray 700  |

디자인에서 사용하는 이름은 그대로 유지하고, 실제 연결되는 컬러 값만 변경하는 방식이야.

## **9. 프론트엔드 연결**

컬러 토큰은 CSS 변수로 관리할 수 있어.

```
:root {
  /* Primitive Tokens */
  --blue-500: #3b82f6;
  --gray-900: #111827;
  --gray-200: #e5e7eb;

  /* Alias Tokens */
  --color-action-primary: var(--blue-500);
  --color-text-primary: var(--gray-900);
  --color-border-default: var(--gray-200);
}

[data-theme="dark"] {
  --color-text-primary: #ffffff;
  --color-border-default: #374151;
}
```

컴포넌트에서는 실제 색상값 대신 역할을 가진 변수를 사용해.

```
.primary-button {
  background-color: var(--color-action-primary);
}

.heading {
  color: var(--color-text-primary);
}
```

## **핵심 요약**

1. UI 컬러는 화면을 꾸미는 것보다 정보와 행동의 우선순위를 구분하는 것이 중요하다.
2. 컬러는 브랜드, 액션, 중립, 시맨틱 컬러로 구분한다.
3. 강조 컬러는 중요한 요소에 제한적으로 사용한다.
4. 텍스트의 중요도에 따라 컬러 위계를 설정한다.
5. 명도 대비를 확인하고 색상만으로 상태를 전달하지 않는다.
6. 하나의 색상도 여러 단계로 구성해 UI 상태에 활용한다.
7. Primitive Token은 실제 색상 값, Alias Token은 사용 목적을 나타낸다.
8. Alias Token을 활용하면 다크 모드와 컬러 변경을 쉽게 관리할 수 있다.

**가장 중요한 개념:** 컬러를 단순히 `파란색`, `회색`으로 관리하는 것이 아니라 `Action Primary`, `Text Primary`처럼 **역할 중심으로 관리하는 것**이 디자인 시스템의 핵심이야.
