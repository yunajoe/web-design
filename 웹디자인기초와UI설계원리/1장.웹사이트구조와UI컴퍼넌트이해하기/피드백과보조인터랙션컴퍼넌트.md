# **피드백과 보조 인터랙션을 만드는 컴포넌트**

## **1. 피드백 UI가 중요한 이유**

피드백 UI는 **사용자의 행동과 시스템의 현재 상태를 시각적으로 전달하는 요소**야.

예를 들어:

- 저장 버튼을 누르면 저장 완료 안내
- 파일 업로드 중에는 진행률 표시
- 삭제처럼 되돌리기 어려운 행동은 재확인
- 데이터를 불러오는 동안 로딩 표시
- 아이콘의 의미는 툴팁으로 설명

## **2. 피드백 컴포넌트 종류**

| 컴포넌트        | 목적                    | 사용 예시               |
| --------------- | ----------------------- | ----------------------- |
| 얼럿(Alert)     | 주의 및 결정 요구       | 계정 삭제 확인          |
| 토스트(Toast)   | 행동 결과 전달          | 저장 완료, 복사 완료    |
| 배지(Badge)     | 상태 및 변화 표시       | 읽지 않은 알림          |
| 로딩(Loading)   | 처리 중임을 표시        | 데이터 불러오기         |
| 프로그레스 바   | 작업 진행률 표시        | 파일 업로드             |
| 툴팁(Tooltip)   | 짧은 보조 설명          | 아이콘 기능 안내        |
| 팝오버(Popover) | 추가 정보와 간단한 행동 | 프로필 메뉴             |
| 모달(Modal)     | 특정 작업에 집중        | 회원가입, 프로젝트 생성 |

**사용자 흐름을 방해하는 정도**

배지 → 토스트 → 툴팁 → 팝오버 → 얼럿·모달 순으로 대체로 강해져. 로딩과 프로그레스 바는 작업 상황에 따라 달라져

## **3. 컴포넌트별 상세 정리**

### **① 얼럿(Alert)**

사용자의 주의가 필요하거나 특정 결정을 요구하는 메시지.

**사용 상황**

- 계정 및 프로젝트 삭제
- 저장하지 않고 페이지 이동
- 중요한 설정 변경
- 결제 및 플랜 업데이트

**설계 시 주의사항**

- 반드시 확인이 필요한 상황에 사용
- 어떤 행동이 실행되는지 버튼 문구로 명확하게 표현
- 위험한 행동은 시각적으로 구분
- 더 안전한 선택이 무엇인지 강조

예시: `삭제하기` / `취소`

단순히 `확인`이라고 쓰기보다는 실행될 행동을 구체적으로 표현하는 것이 좋아.

### **② 토스트(Toast)**

사용자의 행동 결과를 가볍게 전달하는 메시지. 화면을 막지 않고 잠시 나타났다가 사라져.

**대표 유형**

| 유형      | 메시지 예시                       |
| --------- | --------------------------------- |
| 성공      | 저장되었습니다.                   |
| 오류      | 저장하지 못했습니다.              |
| 정보      | 새로운 버전이 업데이트되었습니다. |
| 액션 포함 | 삭제되었습니다. 실행 취소         |

**설계 시 주의사항**

- 일반적인 표시 시간은 약 3\~5초
- 주요 콘텐츠나 입력 영역을 가리지 않도록 배치
- 중요한 행동을 토스트 안에서만 제공하지 않기
- 불필요한 토스트 남용하지 않기

### **③ 배지(Badge)**

상태나 새로운 변화가 있다는 사실을 작게 표시하는 컴포넌트.

**사용 상황**

- 읽지 않은 알림 개수
- 새로운 메시지
- 승인 완료
- 검토 필요
- 상품 재고 상태

| 색상   | 일반적인 의미              |
| ------ | -------------------------- |
| 빨간색 | 긴급, 오류, 읽지 않은 알림 |
| 파란색 | 안내, 정보, 새로운 소식    |
| 노란색 | 주의, 확인 필요            |
| 초록색 | 정상, 완료, 승인           |
| 회색   | 비활성화, 보조 상태        |

**설계 시 주의사항**

- 색상만으로 상태를 전달하지 않기
- 텍스트, 아이콘, 숫자 등을 함께 활용
- 서비스 전체에서 색상의 의미를 일관되게 유지
- 배지를 지나치게 많이 사용하지 않기

### **④ 로딩(Loading)**

데이터 처리나 작업이 진행 중이라는 사실을 알려주는 피드백.

| 유형            | 특징                      | 적합한 상황         |
| --------------- | ------------------------- | ------------------- |
| 스피너          | 처리 중임을 표시          | 짧은 작업           |
| 스켈레톤 UI     | 콘텐츠 영역을 미리 표현   | 카드 목록 로딩      |
| 로티 애니메이션 | 브랜드 분위기 표현        | 개성 있는 로딩 화면 |
| 버튼 내부 로딩  | 클릭한 버튼에서 상태 표시 | 저장, 로그인        |

**설계 시 주의사항**

- 스켈레톤은 실제 콘텐츠의 크기와 형태를 반영
- 애니메이션은 전달력과 성능을 고려
- 버튼 내부 로딩 중에는 중복 클릭 방지

### **⑤ 프로그레스 바(Progress Bar)**

작업의 현재 진행률이나 단계를 보여주는 컴포넌트.

**사용 상황**

- 파일 업로드 및 다운로드
- 설문 작성
- 회원가입 단계
- 결제 과정
- 온보딩

예시:

- `65% 업로드됨`
- `총 4단계 중 2단계`

**스피너와 차이**

| 구분      | 스피너                      | 프로그레스 바                |
| --------- | --------------------------- | ---------------------------- |
| 전달 정보 | 작업 진행 중                | 작업 진행 정도               |
| 진행률    | 알 수 없음                  | 확인 가능                    |
| 사용 상황 | 짧거나 진행률을 모르는 작업 | 진행률을 계산할 수 있는 작업 |

실제 작업 상태와 진행률을 일치시키는 것이 중요해.

### **⑥ 툴팁(Tooltip)**

아이콘이나 버튼의 의미를 보완하는 짧은 설명.

**사용 상황**

- 아이콘 버튼 기능 설명
- 생소한 용어 안내
- 비활성화된 기능의 이유
- 입력 조건 안내

**설계 시 주의사항**

- 가능하면 한 줄 이내로 짧게 작성
- 툴팁 없이도 기본 기능을 이해할 수 있어야 함
- 데스크톱의 호버뿐 아니라 키보드 포커스와 모바일 터치도 고려

### **⑦ 팝오버(Popover)**

특정 요소를 선택했을 때 열리는 보조 정보 창. 툴팁보다 많은 정보를 담을 수 있고 버튼이나 링크도 포함할 수 있어.

**사용 상황**

- 사용자 프로필 요약
- 일정 미리보기
- 알림 상세 정보
- 필터 설정
- 간단한 설정 변경

**닫는 방법**

- 닫기 버튼
- 열었던 버튼 다시 선택
- 바깥 영역 선택
- ESC 키

### **⑧ 모달(Modal)**

현재 화면 위에 표시되어 특정 정보나 행동에 집중하도록 만드는 컴포넌트.

모달이 열리면 일반적으로 뒤에 있는 페이지와 상호작용할 수 없어.

**사용 상황**

- 중요한 정보 확인
- 삭제 확인
- 로그인 및 회원가입
- 간단한 프로젝트 생성
- 짧은 폼 작성
- 콘텐츠 상세 보기

**기본 구성**

- 제목과 설명
- 본문 콘텐츠
- 입력 요소
- 주요 행동 버튼
- 취소 또는 닫기 버튼
- 배경 오버레이

**설계 시 주의사항**

- 닫기 버튼, 취소 버튼, ESC 키 등 종료 방법 제공
- 작성 중인 데이터가 사라질 수 있다면 닫기 전 확인
- 입력 필드가 너무 많거나 작업이 복잡하면 별도 페이지 고려

## **4. 툴팁 vs 팝오버 vs 모달**

| 구분          | 툴팁        | 팝오버                  | 모달                     |
| ------------- | ----------- | ----------------------- | ------------------------ |
| 목적          | 짧은 설명   | 추가 정보와 간단한 행동 | 특정 작업에 집중         |
| 표시 방식     | 호버·포커스 | 클릭·탭                 | 화면 중앙                |
| 정보량        | 매우 적음   | 보통                    | 많음                     |
| 상호작용      | 거의 없음   | 내부 버튼·링크 가능     | 입력 및 다양한 행동 가능 |
| 배경 상호작용 | 가능        | 가능한 경우가 많음      | 일반적으로 제한          |
| 흐름 방해     | 낮음        | 중간                    | 높음                     |

- 툴팁: 아이콘의 기능을 알려줄 때
- 팝오버: 메뉴나 추가 정보를 보여줄 때
- 모달: 삭제 확인이나 프로젝트 생성처럼 집중이 필요할 때

## **5. 피드백 UI에서 자주 발생하는 실수**

- 모든 메시지를 모달로 표시하기
- 중요한 내용을 자동으로 사라지는 토스트로만 전달하기
- 토스트 표시 시간이 너무 짧기
- 토스트가 입력 영역을 가리기
- 배지를 지나치게 많이 사용하기
- 로딩 중 중복 클릭을 허용하기
- 진행률을 알 수 있는 작업에 스피너만 사용하기
- 툴팁에 긴 설명을 넣기
- 호버에만 의존하기
- 모달 안에 지나치게 많은 기능을 넣기
- 모달을 닫는 방법을 명확하게 제공하지 않기

## **핵심 요약**

1. 피드백 UI는 사용자의 행동에 대한 시스템 상태를 전달한다.
2. 메시지의 중요도와 사용자의 행동 필요성에 따라 컴포넌트를 선택한다.
3. 얼럿과 모달은 사용자의 흐름을 중단시키므로 필요한 상황에만 사용한다.
4. 스피너는 처리 중임을, 프로그레스 바는 진행 정도를 전달한다.
5. 툴팁은 짧은 설명, 팝오버는 추가 정보와 간단한 행동에 적합하다.
6. 모바일 터치와 키보드 포커스 등 다양한 입력 방식도 고려한다.

**프론트엔드 연결**

| ------------- | -------------------- |
| 얼럿          | AlertDialog          |
| 토스트        | Toast                |
| 배지          | Badge                |
| 로딩          | Spinner, Skeleton    |
| 프로그레스 바 | Progress             |
| 툴팁          | Tooltip              |
| 팝오버        | Popover              |
| 모달          | Dialog               |
