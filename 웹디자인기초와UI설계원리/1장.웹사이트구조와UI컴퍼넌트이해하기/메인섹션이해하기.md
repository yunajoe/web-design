# **5강. 웹에서 메인 섹션 이해하기**

디자인베이스 · 웹 디자인 기초와 UI 설계 원리

## **1. 핵심 개념**

**메인(Main)은 웹페이지에서 가장 핵심적인 콘텐츠가 배치되는 영역이다.**

메인은 하나의 큰 콘텐츠가 아니라, 서로 다른 주제와 목적을 가진 여러 개의 **섹션(Section)** 으로 구성된다.

예를 들어 서비스 소개 페이지는 다음과 같이 구성할 수 있다.

- 서비스의 핵심 메시지
- 주요 기능과 가치
- 실제 이용 사례와 성과
- 자주 묻는 질문
- 회원가입 및 문의 유도

각 섹션은 서로 다른 역할을 하지만 페이지 전체에서는 하나의 목표를 향해 연결되어야 한다.

## **2. 섹션(Section)이란?**

**하나의 의미 있는 주제나 목적을 담당하는 콘텐츠 영역이다.**

예를 들어 다음과 같이 구분할 수 있다.

| 섹션        | 목적                           |
| ----------- | ------------------------------ |
| 서비스 소개 | 어떤 서비스를 제공하는지 설명  |
| 기능 소개   | 주요 기능을 이해시킴           |
| 고객 사례   | 실제 성과를 보여주어 신뢰 형성 |
| FAQ         | 사용자의 질문과 망설임 해소    |
| CTA         | 문의나 구매 행동 유도          |

주의할 점은 배경색이나 여백이 달라졌다고 반드시 별개의 섹션은 아니라는 것이다.

**구분 기준은 시각적인 모양이 아니라 주제와 역할이다.**

### **각 섹션을 한 문장으로 정의해야 하는 이유**

섹션을 설계할 때 먼저 목적을 한 문장으로 정리한다.

예시:

- 첫 번째 섹션: 우리가 어떤 서비스를 제공하는지 알린다.
- 두 번째 섹션: 사용자가 얻을 수 있는 결과를 설명한다.
- 세 번째 섹션: 고객 사례와 수치로 신뢰를 만든다.
- 마지막 섹션: 프로젝트 문의를 유도한다.

목적을 한 문장으로 설명하기 어렵다면 하나의 영역에 너무 많은 내용이 섞여 있는지 검토해야 한다.

## **3. 섹션은 사용자의 인지 흐름에 따라 배치한다**

처음 방문한 사용자는 웹사이트에 대해 아는 정보가 거의 없다.

일반적으로 다음과 같은 질문을 순서대로 생각한다.

1. 여기는 무엇을 하는 곳일까?
2. 이 서비스는 나에게 어떤 도움이 될까?
3. 어떤 기능과 장점이 있을까?
4. 정말 믿고 사용해도 괜찮을까?
5. 사용하거나 구매하려면 어떻게 해야 할까?

따라서 메인 섹션도 이러한 질문에 답하도록 구성하는 것이 좋다.

**사용자의 인지 흐름**

**① 이해**

이 사이트는 무엇을 제공하는가?

**② 가치와 공감**

나에게 어떤 도움이 되는가?

**③ 신뢰**

믿고 사용해도 괜찮은가?

**④ 행동**

가입, 구매, 문의하기

**웹페이지에 접속했을 때 스크롤을 내리기 전에 가장 먼저 보이는 대표 영역이다.**

### **히어로 섹션의 역할**

사용자가 짧은 시간 안에 다음 내용을 이해하도록 돕는다.

- 이 사이트는 무엇을 하는 곳인가?
- 누구를 위한 서비스인가?
- 어떤 가치를 얻을 수 있는가?
- 다음으로 어떤 행동을 할 수 있는가?

### **기본 구성 요소**

| 요소          | 설명                                |
| ------------- | ----------------------------------- |
| 핵심 헤드라인 | 서비스의 핵심 가치 전달             |
| 짧은 설명     | 헤드라인의 내용을 보완              |
| 주요 CTA      | 가장 중요한 행동 유도               |
| 보조 CTA      | 추가적인 행동 제공                  |
| 대표 이미지   | 서비스 화면이나 제품 이미지         |
| 영상·쇼릴     | 서비스나 작업물의 시각적 소개       |
| 신뢰 정보     | 필요한 경우 고객사나 성과 정보 제공 |

### **CTA는 한두 가지에 집중한다**

너무 많은 행동을 동시에 제안하면 사용자가 무엇을 선택해야 할지 판단하기 어렵다.

예시:

**서비스형 웹사이트**

**무료로 시작하기**

데모 예약하기

주요 CTA는 채워진 버튼, 보조 CTA는 외곽선 버튼으로 구분한 예시

포트폴리오 사이트라면 다음과 같이 구성할 수 있다.

- 주요 CTA: 프로젝트 보기
- 보조 CTA: 작업 문의하기

## **6. 가치와 기능을 설명하는 섹션**

히어로 섹션에서 서비스의 정체성을 이해한 사용자는 다음으로 자신에게 어떤 도움이 되는지 궁금해한다.

이때 기능 자체보다 **기능을 통해 사용자가 얻는 결과와 가치**를 중심으로 설명하는 것이 좋다.

### **기능 중심 vs 결과 중심**

| 기능 중심        | 결과 중심                               |
| ---------------- | --------------------------------------- |
| 자동화 기능 제공 | 반복 업무를 자동화하여 작업 시간 절약   |
| 검색 기능 제공   | 원하는 상품을 빠르게 찾을 수 있음       |
| 통계 기능 제공   | 데이터를 바탕으로 성과를 파악할 수 있음 |

기능 섹션에는 다음 내용을 포함할 수 있다.

1. 사용자가 겪는 문제
2. 해당 기능이 문제를 해결하는 방식
3. 기능을 사용했을 때 얻는 결과
4. 실제 사용 화면이나 활용 예시

**모든 기능을 메인 페이지에 보여줄 필요는 없다.**

기능이 20\~30개 있더라도 핵심 기능 3\~5개를 선별하고 나머지는 별도 페이지로 연결할 수 있다.

### **신뢰 섹션에 활용할 수 있는 요소**

| 요소          | 설명                         |
| ------------- | ---------------------------- |
| 사용자 후기   | 실제 사용자의 경험           |
| 고객사 로고   | 서비스를 이용하는 기업       |
| 이용자 수     | 서비스 이용 규모             |
| 프로젝트 수   | 완료한 프로젝트 규모         |

| 케이스 스터디 | 문제 해결 과정과 결과        |
| 보안 안내     | 개인정보 및 데이터 보호 정보 |

이러한 요소를 활용해 신뢰를 형성하는 것을 **소셜 프루프(Social Proof)** 라고 한다.

### **신뢰 요소의 배치**

신뢰 정보는 페이지 한 곳에만 배치할 필요가 없다.

사용자가 결정을 고민하는 지점 근처에 배치할 수 있다.

- 가격 섹션 주변: 고객 후기, 환불 정책
- 회원가입 버튼 주변: 고객사 및 이용자 정보
- 구매 버튼 주변: 상품 리뷰
- 문의 양식 주변: 프로젝트 사례 및 성과

### **성과 수치를 사용할 때 주의점**

단순히 숫자만 크게 보여주는 것이 아니라 무엇을 의미하는지 설명해야 한다.

예시:

- 프로젝트 완료 120건
- 평균 전환율 35% 개선
- 누적 사용자 10만 명
- 고객사 재계약률 92%
- 업무 시간 주당 8시간 절감

수치는 측정 조건과 기간 등 근거를 함께 제공해야 한다.

### **페이지 마지막에 CTA를 다시 배치하는 이유**

사용자가 첫 화면에서 바로 행동하지 않을 수 있기 때문이다.

기능, 사례, 성과, 후기를 확인한 뒤에는 서비스에 대한 이해와 신뢰가 높아진다.

따라서 페이지 하단에서 CTA를 다시 제공하면 사용자가 위로 돌아가지 않고 바로 행동할 수 있다.

**중요:** CTA는 여러 행동을 동일하게 강조하기보다 페이지의 핵심 목표 하나에 집중하는 것이 좋다.

## **11. 메인 섹션 설계 시 확인할 3가지**

**① 하나의 주제와 목적에 집중했는가?**

하나의 섹션에 너무 많은 내용을 넣으면 정보 전달력이 떨어진다.

확인 질문: 이 섹션은 사용자가 무엇을 이해하거나 행동하도록 돕는가?

**② 전체 흐름을 끊는 섹션은 없는가?**

앞의 섹션에서 생긴 질문에 다음 섹션이 답하도록 구성한다.

예: 기능 설명 → 실제 사용 사례 → 성과 → CTA

**③ 중요한 내용을 먼저 보여주고 있는가?**

사용자가 페이지 끝까지 읽는다는 보장은 없다.

따라서 사이트의 핵심 메시지와 대표 콘텐츠를 위쪽에 배치한다.

## **12. 메인 섹션 설계 과정**

실제로 웹사이트를 제작할 때는 다음 순서로 진행한다.

1. **페이지의 목표를 정한다.**

   사용자가 최종적으로 어떤 행동을 하기를 원하는지 결정한다.

   예: 회원가입, 상품 구매, 프로젝트 문의, 앱 다운로드

2. **사용자의 질문을 정리한다.**
   - 이곳은 무엇을 하는 곳인가?
   - 나에게 어떤 도움이 되는가?
   - 어떤 기능이 있는가?
   - 실제로 믿을 수 있는가?
   - 비용은 얼마인가?
   - 어떻게 시작하는가?
3. **필요한 섹션을 나열한다.**

   디자인을 먼저 만들기보다 섹션 이름과 목적을 문장으로 정리한다.

4. **우선순위를 조정한다.**

   핵심 메시지는 위쪽에, 보조 정보는 아래쪽이나 별도 페이지에 배치한다.

5. **섹션 사이의 흐름을 확인한다.**

   제목만 순서대로 읽어도 자연스럽게 이해되는지 확인한다.

6. **각 섹션의 콘텐츠를 구체화한다.**

   제목, 설명, 이미지, 데이터, CTA 등을 설계한다.

## **13. 핵심 요약**

**메인 섹션의 기본 흐름**

# **이해 → 가치 → 신뢰 → 행동**

| 용어         | 핵심 의미                             |
| ------------ | ------------------------------------- |
| Section      | 하나의 주제와 목적을 가진 콘텐츠 영역 |
| Hero         | 처음 방문했을 때 보이는 대표 영역     |
| Feature      | 주요 기능과 사용자 가치 설명          |
| Social Proof | 후기와 성과 등을 통한 신뢰 형성       |
| CTA          | 사용자의 목표 행동 유도               |
| Case Study   | 문제 해결 과정과 실제 성과 소개       |
| Integration  | 다른 서비스와의 연동 정보             |
| FAQ          | 자주 묻는 질문과 답변                 |
| Pricing      | 가격과 요금제 안내                    |

**가장 중요한 내용**

좋은 메인 페이지는 섹션이 많은 페이지가 아니다.

사용자의 질문에 순서대로 답하고, 각 섹션이 하나의 목적을 담당하며, 최종적으로 사용자가 원하는 행동을 하도록 자연스럽게 연결하는 페이지다.

## **프론트엔드 개발 관점에서 연결하기**

이 개념은 실제 React 컴포넌트 설계와도 연결돼.

```
function LandingPage() {
  return (
    <>
      <Header />

      <main>
        <HeroSection />
        <FeatureSection />
        <CustomerSection />
        <CaseStudySection />
        <FAQSection />
        <CTASection />
      </main>

      <Footer />
    </>
  )
}
```

각 섹션을 독립적인 컴포넌트로 분리하면 재사용과 유지보수가 쉬워지고, 섹션별 역할도 명확해진다.
