# **4강. 어디에 무엇을 배치할까? 웹사이트 기본 구조와 역할 완벽 정리**

디자인베이스 · 웹 디자인 기초와 UI 설계 원리

## **1. 핵심 개념**

**웹사이트는 일반적으로 헤더(Header), 메인(Main), 사이드바(Sidebar), 푸터(Footer)라는 기본 영역으로 구성된다.**

각 영역은 단순히 화면을 나누기 위한 것이 아니라 서로 다른 역할을 수행한다.

- 헤더: 사이트의 정체성과 주요 이동 경로 제공
- 메인: 핵심 콘텐츠와 사용자 행동 제공
- 사이드바: 보조 정보와 탐색 기능 제공
- 푸터: 정책, 회사 정보, 고객지원 등 제공

모든 웹사이트에 네 가지 영역이 반드시 필요한 것은 아니며, 서비스 목적에 따라 구성을 달리할 수 있다.

## **3. 멘탈 모델과 어포던스**

## **4. 헤더 (Header)**

**웹사이트의 가장 상단에 위치하며 사이트의 정체성과 주요 이동 경로를 제공하는 영역이다.**

| --------------- | --------------------------- |

### **로고 (Logo)**

- 브랜드를 보여주는 요소다.
- 일반적으로 헤더 왼쪽이나 중앙에 배치한다.
- 로고를 클릭하면 홈페이지로 이동하도록 설계하는 경우가 많다.

### **내비게이션 (Navigation)**

- 웹사이트의 주요 페이지로 이동하는 메뉴 구조다.
- 메뉴가 적으면 헤더에 바로 노출한다.
- 하위 메뉴가 많으면 드롭다운 등의 방식으로 제공할 수 있다.
- 내부 용어보다는 사용자가 이해하기 쉬운 메뉴 이름을 사용하는 것이 좋다.

### **CTA (Call To Action)**

**사용자가 특정 행동을 하도록 유도하는 요소다.**

대표적인 예시:

- 무료로 시작하기
- 회원가입
- 문의하기
- 데모 신청
- 서비스 이용하기

주요 CTA는 일반 메뉴와 시각적으로 구분해야 한다. 여러 버튼을 모두 강조하면 핵심 행동을 구분하기 어려워진다.

### **헤더 설계 시 확인 사항**

- 로고를 쉽게 발견할 수 있는가?
- 주요 메뉴의 의미가 명확한가?
- 현재 선택된 메뉴를 구분할 수 있는가?
- 가장 중요한 CTA가 명확한가?
- 메뉴가 너무 많지 않은가?
- 모바일에서도 주요 기능을 사용할 수 있는가?

## **5. 메인 (Main)**

**웹사이트에서 가장 중요한 콘텐츠가 배치되는 영역이다.**

[dribbble.com](https://dribbble.com/shots/26971748-Modern-SaaS-Landing-Page-UI-Design?utm_source=chatgpt.com)

메인에는 다음과 같은 콘텐츠가 들어갈 수 있다.

- 서비스 소개
- 상품 및 콘텐츠 목록
- 포트폴리오
- 블로그 및 뉴스
- 검색 결과
- 회원가입 양식
- 상품 상세 정보
- 구매 및 결제
- 고객 후기
- FAQ

### **메인은 여러 섹션으로 구성된다**

예를 들어 서비스 소개 페이지는 다음과 같이 구성할 수 있다.

**01. 핵심 메시지 (Hero)**

서비스가 무엇인지 소개

**02. 주요 기능**

어떤 기능을 제공하는가?

**03. 사용 방법**

어떻게 이용하는가?

**04. 서비스 장점 및 고객 후기**

왜 이 서비스를 선택해야 하는가?

**05. 요금제 및 FAQ**

가격과 자주 묻는 질문

**06. 마지막 CTA**

서비스 시작 및 회원가입 유도

### **메인 설계 시 확인 사항**

1. 사용자가 가장 먼저 알아야 할 내용은 무엇인가?
2. 페이지의 가장 중요한 목표 행동은 무엇인가?
3. 콘텐츠를 어떤 순서로 읽어야 자연스러운가?
4. 각 섹션의 역할이 구분되는가?
5. 불필요하거나 반복되는 섹션은 없는가?
6. 중요한 콘텐츠가 장식 요소에 묻히지 않는가?

**핵심:** 모든 콘텐츠를 동일하게 강조하지 않고 정보의 중요도에 따라 시각적 위계를 만들어야 한다.

### **사이드바가 필요한 경우**

- 콘텐츠 카테고리가 많을 때
- 여러 조건으로 검색 결과를 필터링할 때
- 페이지 내부에서 이동할 항목이 많을 때
- 반복적으로 사용하는 보조 기능이 있을 때

### **필요하지 않은 경우**

- 하나의 메시지에 집중하는 랜딩 페이지
- 간단한 회사 소개 페이지
- 이미지 중심의 포트폴리오
- 단일 작업에 집중하는 입력 화면
- 콘텐츠가 적은 소규모 웹사이트

- 브랜드의 일관성을 유지할 수 있다.
- 정책과 운영 정보를 공통으로 제공할 수 있다.

단, 로그인이나 결제처럼 하나의 작업에 집중해야 하는 화면에서는 헤더와 푸터를 단순화할 수 있다.

## **8. 사이트 유형별 기본 구조 비교**

사이트의 목적에 따라 각 영역에 들어가는 콘텐츠가 달라진다.

| 유형        | 헤더                     | 메인                    | 사이드바          | 푸터            |
| ----------- | ------------------------ | ----------------------- | ----------------- | --------------- |
| 서비스 소개 | 로고, 요금제, 문의       | 서비스 소개, 기능, 후기 | 생략 가능         | 회사 정보, 정책 |
| 블로그·뉴스 | 주제, 검색               | 최신 글, 추천 글        | 카테고리, 인기 글 | 전체 카테고리   |
| 중고거래    | 검색, 주요 메뉴          | 상품 목록               | 지역, 가격 필터   | 고객지원, 정책  |
| 쇼핑몰      | 카테고리, 검색, 장바구니 | 상품, 프로모션          | 브랜드, 가격 필터 | 배송·교환, 약관 |

## **9. 실제 웹사이트 분석 방법**

실제 웹사이트를 볼 때 다음 순서로 분석하면 된다.

STEP 1

**헤더 분석**

- 로고는 어디에 있는가?
- 주요 메뉴는 몇 개인가?
- 가장 강조된 CTA는 무엇인가?

STEP 2

**메인 분석**

- 첫 화면에서 어떤 메시지를 전달하는가?
- 콘텐츠는 어떤 순서로 배치되어 있는가?
- 사용자의 행동을 유도하는 지점은 어디인가?

STEP 3

**사이드바 분석**

- 어떤 보조 기능을 제공하는가?
- 메인 콘텐츠의 탐색에 도움이 되는가?
- 모바일에서는 어떻게 변경되는가?

STEP 4

**푸터 분석**

- 이용약관과 개인정보처리방침이 있는가?
- 회사 정보와 고객지원 경로가 있는가?
- 추가 이동 경로가 제공되는가?

## **10. 웹사이트 구조 설계 시 자주 하는 실수**

| 잘못된 설계                   | 개선 방향                      |
| ----------------------------- | ------------------------------ |
| 모든 요소를 독창적으로 배치   | 사용자가 익숙한 구조 유지      |
| 헤더에 너무 많은 메뉴 배치    | 핵심 메뉴만 우선 노출          |
| 모든 콘텐츠를 동일하게 강조   | 정보의 중요도에 따라 위계 설정 |
| 관습적으로 사이드바 추가      | 실제 탐색에 필요한지 판단      |
| 푸터에 남은 정보를 전부 배치  | 정보 성격에 따라 그룹화        |
| 디자인만 고려하고 기능을 놓침 | 기능과 역할을 먼저 정의        |

## **핵심 요약**

**웹사이트 기본 구조 4가지**

# **Header → Main → Sidebar → Footer**

1. **Header**: 사이트의 정체성과 주요 이동 경로
2. **Main**: 핵심 콘텐츠와 사용자 행동
3. **Sidebar**: 보조 정보와 탐색 기능
4. **Footer**: 정책, 회사 정보, 고객지원

**함께 기억할 개념**

- 멘탈 모델: 사용자가 기존 경험으로 예상하는 동작
- 어포던스: 화면을 통해 행동 가능성을 전달하는 특성
- CTA: 사용자의 특정 행동을 유도하는 요소
- 레이아웃: 정보와 기능을 역할에 따라 구조화하는 과정

**가장 중요한 내용**

웹디자인은 요소를 예쁘게 배치하는 작업이 아니다. 각 요소의 역할을 먼저 정의하고, 사용자가 익숙하고 자연스럽게 정보를 찾고 행동할 수 있도록 구조를 설계하는 작업이다.

## **프론트엔드 개발 관점에서 연결하기**

이 개념들은 실제 HTML 시맨틱 구조와도 연결돼.

```
<header>
  <!-- 로고, 내비게이션 -->
</header>

<div class="layout">
  <main>
    <!-- 핵심 콘텐츠 -->
  </main>

  <aside>
    <!-- 보조 정보, 필터 -->
  </aside>
</div>

<footer>
  <!-- 회사 정보, 정책 -->
</footer>
```

| HTML 요소  | 웹사이트 영역 |
| ---------- | ------------- |
| `<header>` | 헤더          |
| `<main>`   | 메인          |
| `<aside>`  | 사이드바      |
| `<footer>` | 푸터          |
| `<nav>`    | 내비게이션    |

참고로 HTML의 `<aside>`는 항상 화면 오른쪽 사이드바를 의미하는 것은 아니야. 주변 콘텐츠와 관련된 보조 콘텐츠를 나타내는 시맨틱 요소이다.
