# **6강. 컴포넌트 이해하기: 웹의 뼈대와 흐름을 만드는 컴포넌트**

디자인베이스 · 웹 디자인 기초와 UI 설계 원리

## **1. 핵심 개념**

**컴포넌트(Component)는 웹페이지를 구성하는 재사용 가능한 UI 단위다.**

작은 버튼부터 여러 요소가 조합된 내비게이션 바까지 다양한 형태가 있다.

예를 들어 로그인 화면은 다음 컴포넌트로 구성할 수 있다.

- 이메일 입력창
- 비밀번호 입력창
- 로그인 버튼
- 비밀번호 찾기 링크
- 오류 메시지
- 소셜 로그인 버튼

### **컴포넌트를 사용하는 이유**

1. 반복되는 UI를 효율적으로 제작할 수 있다.
2. 여러 페이지에서 일관된 디자인을 유지할 수 있다.
3. 수정 사항을 관련 화면에 쉽게 반영할 수 있다.
4. 디자이너와 개발자가 동일한 단위로 소통할 수 있다.
5. 기본, 선택, 비활성화 등의 상태를 체계적으로 관리할 수 있다.

### **컴포넌트의 구성 단계**

**작은 컴포넌트**

버튼 · 배지 · 입력창

**조합된 컴포넌트**

카드 · 검색창 · 내비게이션 바

**페이지**

여러 컴포넌트가 조합된 하나의 웹페이지

## **2. 웹의 뼈대와 흐름을 만드는 4가지 컴포넌트**

이번 강의의 핵심은 웹사이트에서 사용자의 위치와 이동을 도와주는 네 가지 컴포넌트다.

1. 내비게이션 바 (Navigation Bar)
2. 브레드크럼 (Breadcrumb)
3. 탭 (Tabs)
4. 페이지네이션 (Pagination)

### **① 메뉴 개수 조절**

메뉴가 너무 많으면 다음과 같은 문제가 발생한다.

- 메뉴 사이 간격이 좁아진다.
- 검색과 로그인 버튼을 배치하기 어려워진다.
- 사용자가 원하는 메뉴를 찾기 어려워진다.
- 모바일 화면에서 레이아웃이 복잡해진다.

따라서 중요한 메뉴를 우선 노출하고 나머지는 하위 메뉴나 푸터로 정리할 수 있다.

**인터뷰 질문지 만들기**

마지막 항목은 현재 페이지

### **브레드크럼이 필요한 이유**

1. 현재 페이지의 위치를 알려준다.
2. 상위 카테고리와 페이지 구조를 보여준다.
3. 이전 단계의 페이지로 이동할 수 있다.
4. 사용자가 사이트 구조를 이해하도록 돕는다.

### **브레드크럼의 특징**

- 일반적으로 상위 경로는 클릭할 수 있다.
- 마지막 항목인 현재 페이지는 클릭할 수 없도록 처리한다.
- 현재 페이지와 상위 경로는 시각적으로 구분한다.
- `>`, `/`, 화살표 등의 구분 기호를 사용한다.

### **모바일에서의 처리**

경로가 길어지면 다음과 같이 처리할 수 있다.

- 일부 중간 경로 생략
- 바로 위 상위 페이지까지만 표시
- 긴 항목 축약
- 필요성이 낮으면 숨김

### **브레드크럼 vs 방문 기록**

헷갈리기 쉬운 개념

브레드크럼은 사용자가 이전에 방문한 페이지의 기록이 아니다.

사이트의 실제 정보 구조에서 현재 페이지가 어디에 속하는지를 나타낸다.

### **① 페이지네이션이 필요한 이유**

- 한 번에 너무 많은 데이터를 불러오는 것을 방지
- 초기 로딩 시간 관리
- 콘텐츠를 일정한 단위로 구분
- 사용자가 현재 위치와 전체 결과를 파악하도록 지원

### **② 기본 구성 요소**

이전

1

2

3

...

10

다음

2페이지가 현재 선택된 상태

- 현재 페이지
- 이동 가능한 페이지 번호
- 이전 페이지 버튼
- 다음 페이지 버튼
- 필요한 경우 처음과 마지막 페이지 버튼

페이지가 많으면 모든 번호를 표시하지 않고 말줄임표를 사용할 수 있다.

`이전 1 … 8 9 10 11 12 … 30 다음`

### **세 가지 방식 비교**

| 구분        | 페이지네이션     | 더보기                | 무한 스크롤                   |
| ----------- | ---------------- | --------------------- | ----------------------------- |
| 콘텐츠 추가 | 페이지 이동      | 버튼 클릭             | 자동 추가                     |
| 사용자 제어 | 페이지 선택      | 추가 시점 선택        | 자동 로딩                     |
| 현재 위치   | 파악하기 쉬움    | 불러온 목록에서 유지  | 파악하기 어려울 수 있음       |
| 주요 장점   | 결과 범위가 명확 | 탐색 흐름 유지        | 연속적인 탐색                 |
| 주의점      | 모바일에서 복잡  | 전체 규모 파악 어려움 | 이전 위치 및 푸터 접근 어려움 |

**어떤 방식이 무조건 좋은 것은 아니다.** 콘텐츠의 종류와 사용자의 목표에 따라 선택해야 한다.

## **7. 네 가지 컴포넌트 한눈에 비교**

이번 강의에서 가장 중요한 비교표

| 컴포넌트      | 주요 역할        | 사용 범위          | 선택 결과           |
| ------------- | ---------------- | ------------------ | ------------------- |
| 내비게이션 바 | 주요 페이지 안내 | 사이트 전체        | 다른 페이지 이동    |
| 브레드크럼    | 현재 위치 안내   | 계층이 깊은 페이지 | 상위 경로 이동      |
| 탭            | 콘텐츠 그룹 전환 | 특정 콘텐츠 영역   | 콘텐츠 변경         |
| 페이지네이션  | 콘텐츠 분할      | 목록 및 검색 결과  | 다른 결과 묶음 이동 |

**기억하는 방법**

- 내비게이션: 어디로 갈까?
- 브레드크럼: 나는 어디에 있을까?
- 탭: 어떤 내용을 볼까?
- 페이지네이션: 다음 목록은 어디에 있을까?

## **8. 컴포넌트 상태 (UI States)**

구조형 컴포넌트는 기본 디자인만 만드는 것으로 끝나지 않는다.

사용자의 행동과 현재 상황을 표현하기 위해 여러 상태를 설계해야 한다.

[Button](https://images.openai.com/static-rsc-4/32lJgdFNv2wqrNw_x6WdkjJIGO6JIE20s6YpnEzZdul-P8EbSk11bG1dmBsLV8STGQ5UmeQSVCJZ26P8w9VQAmF_Lv_1MiInjF9CF1Ns5LsSZVUdxDpvjEhhMJgvjmAYG4T3a85f-vsJlosozlkBnS2mthSIr0qh18W4sUUyQVI?purpose=inline)

[design.digital.gov.my](https://design.digital.gov.my/en/docs/design/button?utm_source=chatgpt.com)

| 상태     | 설명                        | 예시               |
| -------- | --------------------------- | ------------------ |
| Default  | 기본 상태                   | 평상시 버튼        |
| Hover    | 마우스를 올린 상태          | 버튼 색상 변경     |
| Focus    | 키보드 등으로 포커스된 상태 | 입력창 테두리 강조 |
| Active   | 누르는 순간의 상태          | 버튼을 누르는 동안 |
| Selected | 현재 선택된 상태            | 선택된 탭          |
| Disabled | 사용할 수 없는 상태         | 비활성화된 버튼    |

특히 내비게이션, 탭, 페이지네이션에서는 현재 선택된 상태를 명확하게 표현하는 것이 중요하다.

## **9. 프론트엔드 개발 관점에서 연결하기**

이번 강의의 네 가지 컴포넌트는 실제 React 개발에서도 자주 사용해.

| 디자인 개념   | 프론트엔드 구현             |
| ------------- | --------------------------- |
| 내비게이션 바 | `Link`, `NavLink`, 라우팅   |
| 드롭다운      | Dropdown Menu               |
| 브레드크럼    | Breadcrumb 컴포넌트         |
| 탭            | Tabs, 상태 관리             |
| 페이지네이션  | Pagination, API 페이지 요청 |
| 무한 스크롤   | Intersection Observer       |
| 활성 상태     | `usePathname`, 상태값       |
| 반응형 메뉴   | CSS Media Queries           |

예를 들어 React에서는 다음과 같이 구성할 수 있어.

```
function ProductDetail() {
  const [activeTab, setActiveTab] = useState('description')

  return (
    <>
      <Header />

      <Breadcrumb />

      <ProductInfo />

      <Tabs
        value={activeTab}
        onValueChange={setActiveTab}
      />

      <ProductTabContent value={activeTab} />

      <Footer />
    </>
  )
}
```

## **6강에서 기억할 5가지**

1. **컴포넌트**: 재사용 가능한 UI 단위다.
2. **내비게이션**: 사이트의 주요 페이지로 이동한다.
3. **브레드크럼**: 사이트 구조 안에서 현재 위치를 보여준다.
4. **탭**: 같은 화면 안에서 콘텐츠를 전환한다.
5. **페이지네이션**: 많은 콘텐츠를 여러 페이지로 나눈다.
